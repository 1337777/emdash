Status: active; staged retained reviewers and original all-import scope pass with the isolated checker; terminal, further migration and production qualification remain open

This is the consolidated inventory of known remaining obligations, changed
contracts, rejected alternatives and optional follow-up work. It complements
the chronological plan and the detailed owner reviews; it does not replace
their source pins or receipts. An old review saying “next” or “open” is not
automatically a current blocker. Later consumer evidence may supersede it.
Conversely, a passing subset does not discharge an omitted assertion.

The initial source migration can advance past an independent unresolved
observation. Production promotion and completion cannot advance past a broken
required computation. “Revisit after the basic migration” below means before
production qualification for the required rows, and after this goal only for
the explicitly optional rows. No row authorizes a new foundational redesign.

## Current boundary

The selected design still has strict public functors, conventional lax
transformations and displayed maps, public `Hom_Cat = Functor_cat`, and
`Cat_cart` coefficients for admitted families and representable Hom families.
The native identity Homd is followed by an actual composite for general FF.
Q's outer mapping category is Cartesian; its inner `Homd_index_cat` retains
the directed comparisons required by intrinsic action. No new path/equality
argument is supplied by callers.

All implementation remains in the non-library replay. The production kernel
has not been promoted. The [public-ladder evidence][public] qualifies fourteen
general/relative observations. The five terminal expressions now also have
[qualified whole proof-time comparisons][terminal-views]; their stronger
runtime assertions remain positive obligations in the full diagnostic.
The qualified central subset contains 2180 positive and 286 negative
assertions, including the separate comparison/guard reviewer; the full source retains
2162 positives, 278 negatives and all 66 original diagnostic declarations.
These counts describe different scopes and must not be interchanged.
The [source-coverage inventory][component-accumulation-evidence] matches every full-source assertion to
the selected diagnostic drivers except exactly the five R01–R03 obligations.
It also accounts for all 66 declaration names. The [original all-import
execution][checker-boundary] now passes with the isolated batch-snapshot checker:
2435 assertions and all 66 declarations, retaining the same five exclusions.
The [retained-reviewer continuation][retained-reviewers] additionally covers
43 original reviewers / 654 assertions, after correcting two missed original
cokernel/mate consumers and their diagnostic profiles. That checkpoint covered
60 staged registered reviewers and 152 staged registered core files. The
central diagnostic retains the five explicit exclusions.
The [Sigma fibre-inclusion continuation][sigma-fibre] adds two library modules
and one reviewer. Current exact-input evidence covers 154 registered core
files and 61 reviewers, with the same central exclusions. The registry also
contains 637 core files and 535 reviewers not yet staged; their applicable
migration/compatibility work is not silently excluded.
Broader registered-consumer and supported-toolchain qualification remain gates.

Broad source adaptation is not completed computational qualification.
Unchanged diagnostic contracts should migrate mechanically; failures caused
by missing upstream computation remain kernel work. The [Sigma projection
review][cubical-points] adds two native observation-order cuts and one
proof-time source comparison. It leaves the central diagnostic source
unchanged and makes the three former point-clause dispositions explicit.

No operational proof argument, enlarged `(y,v,f)` base or general coend
development is a proposed repair here. A narrower successful alternative
should replace only the affected owner slice; the other obligations remain.

The new represented-inclusion observation is also instructive: observing the
whole Hom yields raw composition while the capped inclusion yields the stable
`Homd_coeff_rep` head. Runtime equality fails in the unchanged source too;
the existing whole proof-time comparison passes. This is an intended
presentation distinction to retain in R06, not a newly discovered invalid
typing or a regression caused by the terminal experiment.

The [matched identity-section review][terminal-identity] narrows the later
canonical-point failure further. Without any candidate contraction, both
the original kernel and the selected migration accept the typed identity
section/component terms but reject the final runtime identity-component
comparison. Their normal forms cross the same constant-section reading.
This is an inherited computational boundary, not evidence that Cat_cart or
strict functors introduce it. It remains relevant to R02 because the eager
terminal normalization exposes that reading. No new rule is adopted and the
five terminal obligations remain open; a native-owner repair must preserve
the actual projection orders rather than normalize arbitrary unit inputs.

The [native-owner experiment][terminal-native] then tested that repair route.
Its generic core pass excludes the five terminal obligations. The terminal
variant's new higher-action failure is distinct from the inherited identity
section boundary. The two general-FF whole views also expose a terminal-source
eta choice for a general section component. A user clarification is pending;
neither their expected polarity nor R03's requirement has been changed.
The selected source and its four recent passing receipt input sets remain
byte-identical. These experiments do not pause independent R08/R10 work.

## Maintenance rule

At each bounded checkpoint, update the affected row with its exact owner,
consumer, disposition and evidence. New failures must be classified as a
required behavior, deliberate interface change, inherited limitation, or
optional improvement. “Passing elsewhere,” extra resource headroom and a
pointwise replacement are not dispositions for a whole failed obligation.

The inventory covers known issues in the active plan, current replay and
`production_*_review.md` records at the stated checkpoint. It is not a claim
that all possible alternatives or future regressions have been discovered.
